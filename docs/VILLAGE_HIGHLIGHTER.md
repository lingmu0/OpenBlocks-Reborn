# 村庄高亮仪（Redux 2）

右键高亮仪开启个人显示并配置。默认单一实时模式，准星指向扫描半径内的床、工作站或钟，显示一位真实关联村民及其 HOME/JOB_SITE/MEETING_POINT 连线。共用钟或多份记忆指向同一方块时，优先选择本次采样中实体 ID 最小的一位；不按距离猜测归属。床脚会对应到床头的 HOME 兴趣点。

“全部快照”只在点击获取按钮时查询。显示 200 tick，冷却 200 tick，正常 20 TPS 下均为 10 秒。进入模式、重新打开界面、改变准星、到期、切换选项都不会自动获取快照。快照中村民位置固定；HUD 标出数据年龄与剩余显示时间。使用的服务端缓存可能比查询时刻早 1–5 秒，分别对应关联、兴趣点与村庄区段。暂停会暂停本地显示计时，服务端卡顿会延长实际冷却时间。

服务端独立限制每位玩家的查询：任意查询至少间隔 10 tick；全部快照至少间隔 200 tick。切换模式或高亮仪、关闭重开界面不会解除冷却。服务端验证高亮仪方块存在、已加载且玩家距离不超过 64 格。

性能边界：

- 扫描半径最多 32 格，只查询已加载区块；关联村民采样在仪器周围 64 格内，最多 128 位。
- 最多 128 个兴趣点、16 位快照村民、48 条快照关联线；单一模式只有一位村民和最多三条连线。达到上限会提示，不能据此认定其他村民没有绑定。
- 关联索引缓存 20 tick，全部兴趣点 40 tick，村庄区段 100 tick；每维最多缓存 32 个仪器/半径组合。
- 客户端在接收快照时整理关联线与外轮廓，避免每帧排序。全部快照使用固定位置，不再逐帧查找实体位置。
- 没有逐帧遍历世界方块，没有为了扫描主动加载区块。缓存命中依然需要构造一次受上限约束的响应。

黄色框为以村民所在方块为基准的 17×13×17 搜索体积。睡眠、附近村民、最近召唤情况、地形和空间等条件仍影响生成。它不是“框内每格一定刷铁”的判断，也不意味着工作站是 Java 版刷铁的必要条件。

蓝色村庄范围默认关闭，依据新版服务端 isVillage 的区段分类绘制外轮廓，最多采样 5×5×5 个区段。它受已加载区块和采样窗口裁剪；窗口边缘可能截断村庄。它随兴趣点占用状态变化，不是铁傀儡生成范围，不沿用旧版木门决定的球形边界。

新高亮仪只做编译、资源与无界面服务端测试；按用户要求未启动客户端，实际画面、界面宽度及大型整合包 FPS 仍需玩家验证。服务端查询计时不能替代客户端性能测量。
